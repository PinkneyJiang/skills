# 需求规范标准实现流水线 (implement)

本技能指导开发者将经过评审的 Spec 技术规格书或任务工单，高质高效地转化为符合生产标准的工程代码。

---

## 实施四步闭环流程

### 1. 拆解垂直切片与测试接缝
- 研读需求 Spec，锁定核心用户故事与实现决策；
- 明确公共测试接缝，严禁直接铺开全量编写；
- 梳理依赖拓扑：优先实现底层领域实体与存储定义，再实现业务服务，最后装配外部控制器与 UI 路由。

### 2. TDD 节奏推进
- 在既定接缝上，编写针对该场景的首个失败测试；
- 实施最小化代码实现使其通过；
- 推进下一个用户故事，循环往复直至所有验收条件达成。

### 3. 全周期静态类型与编译校验
在开发过程中建立**高频的防御性静态检查**：
- **阶段性单文件校验**：每写完一个模块，立即执行该模块专属的单元测试；
- **强类型零容忍检查**：确保没有引入任何隐式 `any`，TypeScript / C# 编译器零报警；
- **全量测试套件验收**：在宣布功能完成前，执行全工程的全量测试套件回归。

### 4. 双轴审查与交付提交
- 调用 `code-review` 技能，对照 Spec 契约与仓库编码规范进行严谨的自检自查；
- 修复自检暴露出的代码坏味道与边界疏漏；
- 编写清晰规范的 Git Commit 消息并提交至工作分支。

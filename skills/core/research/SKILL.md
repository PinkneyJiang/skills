# 权威技术调研与深度评估指南 (research)

本技能用于为复杂的工程决策提供坚实的技术事实支撑。当面临未知的框架特性、第三方服务集成、性能瓶颈机制或技术选型争议时触发。

---

## 调研核心铁律：直击第一手权威信源 (Primary Sources)

绝不依赖二手文章、过时的博客碎片或未经推敲的社区问答。
每一条关键技术推论，必须直接溯源至以下**第一手权威信源**：
1. **官方权威文档**（框架与语言官方维护的最新文档）；
2. **底层开源代码实现**（直接阅读 GitHub / 源码仓库的实现逻辑与单元测试）；
3. **正式技术规范与 RFC**（IETF, W3C, ECMA 标准草案）；
4. **本地验证脚本**（在真实的沙箱环境中编写极简复现验证代码，用执行事实说话）。

---

## 调研报告标准输出格式

调研成果必须输出为结构化的 Markdown 文档，存放在仓库统一的技术评估目录（如 `docs/research/`）：

```markdown
# [技术主题] 调研与可行性评估报告

## 背景与核心问题
清晰阐明发起本次技术调研的具体工程痛点与决策目标。

## 关键结论与技术裁定
用 1-2 段精炼语言明确给出技术结论：可行/不可行？推荐选型是什么？核心限制是什么？

## 核心机制深度解析
- 原理机制拆解；
- 边界约束与已知缺陷（Gotchas）；
- 性能与资源消耗特征。

## 候选方案横向对比矩阵
| 方案 | 易用性 | 性能表现 | 维护成本 | 社区活跃度 | 风险评级 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 方案 A | ... | ... | ... | ... | 低 |
| 方案 B | ... | ... | ... | ... | 中 |

## 验证代码与执行记录
提供在本地沙箱中跑通的最小化验证代码片段及真实输出结果。

## 权威参考依据 (Primary References)
- [官方文档链接与章节]
- [源码仓库 Commit / 行号定位]
```

# 技能创建与评测演进指南 (skill-creator)

本技能用于为智能体创建高质量的新技能，并通过迭代评测持续提升技能的触发准确率与指令执行力。

---

## 高维工作流概览

创建与优化一个技能的高维闭环流程如下：
1. **明确目标意图**：确定技能期望赋予 Agent 何种能力，以及它应该如何拆解和达成目标；
2. **起草初代规范**：编写初版 `SKILL.md`；
3. **构建测试用例集**：编写若干具象的 Prompt 测试样例，并在挂载该技能的 Agent 环境中实际运行；
4. **定性与定量评估**：
   - 检查 Agent 的实际执行路径是否遵循了核心约束；
   - 针对结构化任务，编写确定性的断言或量化指标；
5. **基于反馈重构调优**：根据执行偏差，针对性补充负面案例 (Anti-patterns)、强化门禁规约或细化操作步骤；
6. **调优描述提升触发率 (Triggering Optimization)**：优化 YAML Frontmatter 中的 `description`，确保在相关场景下既不漏触发，也不在无关场景下误触发。

## 技能目录结构解剖 (Anatomy of a Skill)

标准的技能目录结构如下：
```text
skill-name/
├── SKILL.md                 # [必需] 技能核心说明书
│   ├── YAML Frontmatter     # 核心元数据（name、description 必填）
│   └── Markdown 内容        # 规范操作规程、原则、模板与代码示例
└── 附属资源包 (按需选用)
    ├── scripts/             # 可执行脚本（用于确定性、重复性高的重型任务）
    ├── references/          # 深度参考文档（按需在运行时被动态按需读取）
    └── assets/              # 输出产物所需的模版、图标、字体等静态资源
```

## 三层渐进式披露机制 (Progressive Disclosure)

技能采用高效的三级加载体系，以在最大化上下文能力的同时最小化 Token 占用：
1. **第一层：元数据 (Metadata)**
   - 包含 `name` 与 `description`；
   - **常驻上下文**（~100 词），Agent 借此判断当前用户意图是否命中了该技能。
2. **第二层：SKILL.md 正文主体**
   - 仅在技能被命中触发后，才全量载入上下文；
   - 推荐控制在 500 行以内，聚焦在行动纲领、核心决策树与关键模板。
3. **第三层：打包外置资源 (Bundled Resources)**
   - 存放于 `references/` 或 `scripts/` 中；
   - 仅在正文主体指引下按需读取，支持脚本不占 Token 直接在后台静默执行。

## 编写卓越 SKILL.md 的核心法则

### 1. 触发词工程 (Description Engineering)
- `description` 是决定技能能否精准被唤醒的最关键开关；
- **必须同时包含"做什么"与"何时使用"**；
- 鉴于大语言模型普遍存在"触发保守 (Undertriggering)"倾向，描述应当适当具备主动倡导性：
  > *推荐范式*："构建与优化大模型流式 SSE 客户端。**当用户提及流式通信、打字机效果、SSE、SSE 乱码、断线重试或 WebSocket 转 SSE 时务必使用本技能**，即使用户没有明确说出 'SSE' 缩写。"

### 2. 操作规程清晰化 (Workflow-Oriented)
- 避免空洞抽象的说教，提供**带序号的执行步骤 (Numbered SOP)**；
- 明确指出每一个阶段的**完成门禁 (Completion Criteria)**；
- 给出正反两面的对比案例（"✅ 推荐做法" vs "❌ 严禁做法"）。

### 3. 提供开箱即用的代码与骨架模板
- 涉及规范文档产出的，必须提供完整的 Markdown/JSON 模板标签；
- 涉及工程代码实现的，必须提供完整带类型注解的 TypeScript/Python 代码片段。

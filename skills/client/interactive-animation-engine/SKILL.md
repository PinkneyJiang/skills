# 交互式动效工程构建引擎 (interactive-animation-engine)

本技能专为打造经得起苛刻设计工程评审的高水准动效而生。
动效绝非锦上添花的无脑炫技，**它是界面信息流动、状态转换与用户物理直觉的具象表达**。

---

## 动效构建五大严苛门禁法则

在写下任何动效代码前，必须严格依照以下次序顺序推演：

### 阶段 1：判定此元素是否真的需要动？(Should this animate at all?)
| 使用频次 | 决策裁定 | 规约说明 |
| :--- | :--- | :--- |
| **超高频**（每天触发 100+ 次，如快捷键呼出搜索框、命令面板） | **绝对严禁任何动效** | 必须 0ms 瞬间显示。例如 Raycast / VSCode 绝无任何拖沓弹窗动画 |
| **高频**（每天数十次，如列表项悬停、菜单切换） | **近乎无感知微动效** | 耗时控制在 100-150ms 以内，极其轻巧微妙，或干脆纯静态切换 |
| **中频**（模态弹窗、侧边抽屉、气泡通知） | **标准流体物理动画** | 采用临界阻尼弹簧或精准的 ease-out |
| **低频 / 首次体验**（引导流程、成就达成、支付成功） | **充裕的情绪价值动效** | 允许释放创意，展现精致细节与粒子庆祝 |

> 🛑 **红线**：若某个键盘驱动的高频组件试图添加复杂动效，必须直接判定不予添加动效，维持瞬时状态变更。

---

### 阶段 2：明确该动效的唯一核心目的 (What is the purpose?)
必须能用以下六个关键词之一精准命名其意图，否则立即放弃：
1. **反馈 (Feedback)**：向用户证明系统已收到指令；
2. **空间一致性 (Spatial Consistency)**：展示元素来源于何处、消失于何处，防止认知断层；
3. **状态指示 (State Indication)**：让模式与数据变化一目了然；
4. **平滑过渡 (Bridge Change)**：防止视觉内容突然突兀瞬移；
5. **原理解释 (Explanation)**：向用户演示交互手势如何工作；
6. **愉悦惊喜 (Delight)**：仅允许在极低频成功时刻登场。

---

### 阶段 3：工具选型——使用能达成效果的最轻量工具
1. **CSS Transition**：简单的 Hover、按压、颜色与状态切换；
2. **CSS @starting-style**：组件初次挂载挂入 DOM 时的原生入场；
3. **CSS Animation (@keyframes)**：页面首屏加载期间需要脱离主线程由 GPU 独立渲染的循环指示器；
4. **Web Animations API (WAAPI)**：兼具原生性能与精细编程控制力；
5. **Motion (motion.dev)**：弹簧物理学、布局动画（Layout Animation）与复杂手势打断。

---

### 阶段 4：圈定动画属性——坚守 GPU 硬件加速红线
- **仅允许对 `transform` 与 `opacity` 进行动画**：直接由合成器线程处理，跳过昂贵的 Layout（重排）与 Paint（重绘）；
- ❌ **严禁动 `top`、`left`、`margin`、`padding`、`width`、`height`**（手风琴展开收起除外）；
- ❌ **严禁从 `scale(0)` 开始入场**：真实物理世界没有任何物体从体积为零突然膨胀。推荐入场缩放基准为 `scale(0.95 - 0.98)` 配合 `opacity: 0`；
- 在 Motion 库中，始终书写完整的 Transform 字符串以确保硬件合成加速。

---

### 阶段 5：缓动曲线与时间常数矩阵
- **入场动画**：永远采用 `ease-out`（高初速进场，随后优雅减速）；
- **出场动画**：采用极速的 `ease-in` 或比入场短 30% 的 `ease-out`；
- **状态移动/形变**：采用 `ease-in-out`；
- **绝对数值基线**：
  - 微交互（Hover / 按压）：`100ms - 150ms`；
  - 局部状态展开（Dropdown / Toast）：`200ms - 250ms`；
  - 大视口容器（Modal / Sheet）：`300ms - 400ms`。
